# Terraform AWS VPC Module

A reusable and customizable **Terraform module for creating an AWS VPC** with public and private subnets.

This module helps developers create a basic AWS network infrastructure using Terraform without writing the same VPC, subnet, Internet Gateway, and route table configuration repeatedly.

---

## Overview

This Terraform module creates:

* An AWS VPC with a configurable CIDR block
* Multiple public and private subnets
* An Internet Gateway (IGW) when public subnets are configured
* A public route table
* Route table associations for public subnets
* Terraform outputs for VPC and subnet information

### Architecture

```text
                         Internet
                            |
                            |
                    Internet Gateway
                            |
                     Public Route Table
                            |
              +-------------+-------------+
              |                           |
        Public Subnet               Public Subnet
        10.0.0.0/24                 10.0.2.0/24
              |
              |
        Private Subnet
        10.0.1.0/24
```

> **Note:** The current version identifies private subnets but does not create a NAT Gateway or private route tables. Therefore, private subnets do not currently have Internet access through NAT.

---

# Features

* Create an AWS VPC with a custom CIDR block
* Create multiple subnets using `for_each`
* Support public and private subnet configuration
* Automatically create an Internet Gateway when public subnets exist
* Automatically create a public route table
* Automatically associate public subnets with the public route table
* Separate public and private subnet information using Terraform locals
* Strong variable type definitions
* CIDR block validation
* Reusable Terraform module design
* Easy to extend for production use

# File Explanation

## `root-main.tf`

This is the root Terraform configuration.

It calls the reusable VPC module and provides the required VPC and subnet configuration.

Example:

```hcl
module "vpc" {
  source = "./module/vpc"

  vpc_config = {
    vpc_name   = "your-vpc-name"
    cidr_block = "10.0.0.0/16"
  }

  subnet_config = {
    public_subnet = {
      cidr_block = "10.0.0.0/24"
      az         = "eu-north-1a"
      public     = true
    }

    private_subnet = {
      cidr_block = "10.0.1.0/24"
      az         = "eu-north-1b"
    }
  }
}
```

If `public = true`, the subnet is treated as a public subnet.

If `public` is not specified, its default value is `false`, so the subnet is treated as private.

---

# `module/vpc/main.tf`

This file contains the main AWS infrastructure resources.

It creates:

* VPC
* Subnets
* Internet Gateway
* Public Route Table
* Public Route Table Associations

The module uses Terraform `for_each` to dynamically create multiple subnets.

Example concept:

```hcl
resource "aws_subnet" "main" {
  for_each = var.subnet_config

  vpc_id            = aws_vpc.main.id
  cidr_block        = each.value.cidr_block
  availability_zone = each.value.az
}
```

This makes the module reusable because the number of subnets can be changed through configuration.

---

# `module/vpc/variables.tf`

This file defines the input variables required by the module.

The module uses strongly typed Terraform variables such as:

```hcl
vpc_config
subnet_config
```

The subnet configuration contains:

```text
cidr_block
az
public
```

The `public` field defaults to `false`.

Therefore:

```hcl
public = true
```

means the subnet is public.

While:

```hcl
public = false
```

or omitting the field means the subnet is private.

The module also validates CIDR blocks to reduce configuration mistakes.

---

# `module/vpc/outputs.tf`

This file defines the values returned by the VPC module.

Example outputs include:

* VPC ID
* Public subnet information
* Private subnet information
* Public subnet IDs
* Private subnet IDs

These outputs can be consumed by other Terraform resources or modules.

For example, an EC2 module can use the subnet IDs generated by this VPC module.

---

# `root-outputs.tf`

This file exposes the outputs from the VPC module at the root level.

For example:

```hcl
output "vpc_id" {
  value = module.vpc.vpc_id
}
```

This allows you to easily retrieve important infrastructure information using:

```bash
terraform output
```

---

# `module/vpc/versions.tf`

This file defines Terraform and AWS provider requirements.

Example:

```hcl
terraform {
  required_version = ">= 1.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 5.30"
    }
  }
}
```

This helps maintain compatibility between the Terraform configuration and provider versions.

---

# `.terraform.lock.hcl`

This file locks the Terraform provider dependency versions/checksums.

It helps ensure that the same provider versions are used consistently across environments.

**Recommended:** Commit `.terraform.lock.hcl` to Git.

# Usage

## 1. Clone the Repository

```bash
git clone https://github.com/<your-username>/terraform-aws-vpc.git
```

```bash
cd terraform-aws-vpc
```

---

## 2. Initialize Terraform

```bash
terraform init
```

This downloads the required Terraform providers.

---

## 3. Format the Configuration

```bash
terraform fmt -recursive
```

This formats Terraform files according to standard Terraform formatting.

---

## 4. Validate the Configuration

```bash
terraform validate
```

This checks whether the Terraform configuration is syntactically and structurally valid.

---

## 5. Review the Execution Plan

```bash
terraform plan
```

This shows what Terraform will create, modify, or destroy.

---

## 6. Create the Infrastructure

```bash
terraform apply
```

Enter:

```text
yes
```

when Terraform asks for confirmation.

---

## 7. View Outputs

```bash
terraform output
```

You can use this to view:

* VPC ID
* Public subnet IDs
* Private subnet IDs
* Other module outputs

---

## 8. Destroy the Infrastructure

When the infrastructure is no longer required:

```bash
terraform destroy
```

> Use `terraform destroy` carefully because it removes the resources managed by this Terraform configuration.

```hcl
  }

  subnet_config = {

    public_subnet = {
      cidr_block = "10.0.0.0/24"

      public     = true
    }

    private_subnet = {
      cidr_block = "10.0.1.0/24"
      az         = "eu-north-1b"
    }

  }
}
```

# How Public and Private Subnets Work

## Public Subnet

A subnet becomes public when:

```hcl
public = true
```

The module associates the subnet with the public route table.

The public route table contains:

```text
0.0.0.0/0 → Internet Gateway
```

Therefore, resources inside the public subnet can communicate with the Internet when their own configuration also allows it.

Example:

```text
Internet
   |
Internet Gateway
   |
Public Route Table
   |
Public Subnet
   |
EC2
```

---

## Private Subnet

If:

```hcl
public = false
```

or `public` is omitted, the subnet is treated as private by this module.

Example:

```text
VPC
 |
 +-- Public Subnet
 |
 +-- Private Subnet
```

However, in the current implementation, a NAT Gateway is not created.

Therefore, private subnet resources cannot use this module alone to reach the public Internet through NAT.

# Real-World Use Case

This module can be used as the networking foundation for a backend application.

For example:

```text
                    Internet
                       |
                       |
                  Load Balancer
                       |
              +--------+--------+
              |                 |
          Public/Entry      Public/Entry
          Networking        Networking
              |
          Private Subnets
              |
       +------+------+
       |             |
      EC2           EC2
       |             |
       +------+------+
              |
             RDS
```

A typical production architecture can contain:

* Application Load Balancer
* EC2 instances
* Private application subnets
* RDS PostgreSQL
* Redis
* NAT Gateway
* VPC Endpoints
* Security Groups
* IAM Roles

This Terraform module can provide the initial VPC and subnet foundation for such an architecture.

# Current Limitations

This is currently a **basic reusable VPC module**, not a complete production-ready VPC module.

The current version does not create:

* NAT Gateway
* Elastic IP for NAT
* Private route tables
* Private route table associations
* VPC Flow Logs
* VPC Endpoints
* Network ACL customization
* IPv6 configuration
* Multi-AZ NAT Gateway architecture

# Security Considerations

When using this module in production:

* Do not commit AWS access keys or secrets.
* Do not commit `.tfvars` files containing secrets.
* Do not commit Terraform state to a public repository.
* Use IAM roles wherever possible.
* Use Security Groups with least-privilege rules.
* Keep databases in private subnets.
* Use private subnets for application servers where appropriate.
* Use NAT Gateway only when required.
* Prefer VPC endpoints for supported AWS services when appropriate.
* Enable VPC Flow Logs for monitoring where required.
